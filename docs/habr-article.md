# Как я делал кросс-платформенное приложение на .NET MAUI с помощью AI за 10 дней

**TL;DR:** Сделал приложение для семейного бюджета на .NET MAUI — один код для Android, Windows и iOS. AI (opencode/big-pickle) писал ~70% кода. 6000 строк, 38 тестов, опубликовано в RuStore. Вся история — от идеи до публикации.

---

## Зачем

Нужно было приложение для учёта семейного бюджета. Готовые решения — Сбербанк, Тинькофф, Дзен-Мани — не подходили: лишний функционал, обязательная регистрация, данные на чужих серверах. Хотелось простое, локальное, приватное.

Решил сделать сам. Но не тратить 3 месяца. Использовал AI как основного помощника по коду.

## Стек

- **.NET MAUI** — кросс-платформа: Android + Windows + iOS из одного проекта
- **SQLite** (sqlite-net-pcl) — локальная база данных без сервера
- **Microcharts + SkiaSharp** — графики расходов
- **C# / .NET 10** — всё на C#

Итого: **63 файла, ~6000 строк кода, 38 тестов**.

## Что умеет приложение

1. **Учёт доходов и расходов** по категориям (еда, транспорт, жильё и т.д.)
2. **Графики расходов** — за месяц и за 30 дней (Microcharts)
3. **Лимиты по категориям** — уведомления о превышении
4. **Справочник социальных льгот и субсидий** — поиск, фильтрация, обновление по URL
5. **Сценарии «что если»** — моделирование бюджета при изменении дохода/расхода
6. **Быстрые траты** — часто повторяющиеся расходы в один клик
7. **Редактирование и удаление** операций
8. **Тёмная и светлая тема**
9. **Полная приватность** — все данные на устройстве, без серверов

## Как работал с AI

### Модель и инструмент

Использовал **opencode** (CLI-инструмент) с моделью **big-pickle**. Это не просто автодополнение кода — AI:

- Генерировал целые файлы по описанию
- Исправлял баги по логам ошибок
- Делал рефакторинг
- Писал тесты
- Настраивал сборку и публикацию

### Пример workflow

```
Я: "Добавь страницу сценариев — форма с двумя полями (доход, расход), 
    кнопка 'Рассчитать', результат — таблица с прогнозом на 12 месяцев"

AI: [генерирует ScenariosPage.xaml + ScenariosPage.xaml.cs + ScenarioService.cs 
     + ScenarioEngine.cs + 4 теста] — ~400 строк за один шаг
```

### Что AI делал хорошо

- **Boilerplate-код** — DI, сервисы, страницы, стили
- **UI по описанию** — XAML-разметку с корректными стилями
- **Тесты** — писал xUnit-тесты автоматически
- **Исправление ошибок** — по stack trace из лога

### Что AI делал плохо

- **Архитектурные решения** — приходилось перестраивать
- **MAUI-специфика** — много знаний о готчах WinUI/Android нет в тренировочных данных (например, CollectionView с группировкой падает в WinUI)
- **Кодировка** — русские строки в .cs/.xaml ломались при бэкапах
- **Сборка Android** — XAGNM7009 баг, решения приходилось искать самому

## Как публиковать в RuStore

1. **AppId** — зарегистрировал `tech.kuzyacrudit.familybudget`
2. **Keystore** — сгенерировал через `keytool` (RSA 2048, 10000 дней)
3. **APK** — `dotnet publish -f net10.0-android -c Release -p:AndroidPackageFormat=apk`
4. **Скриншоты** — написал C#-скрипт с WinAPI (SetForegroundWindow + CopyFromScreen) — автоматически кликает по табам и делает скриншоты
5. **Политика конфиденциальности** — статичная HTML-страница на GitHub Pages

## Что пошло не так (и как исправлял)

### 1. SQLite не понимает `PRAGMA table_info("Transaction")`

`Transaction` — зарезервированное слово. `QueryAsync<T>` оборачивает PRAGMA в `SELECT … FROM`, что ломает синтаксис.

**Решение:** `SELECT * FROM pragma_table_info('Transaction')` — table-valued function работает.

### 2. CollectionView с группировкой падает в WinUI

NRE в `ItemTemplateContextEnumerable.GetEnumerator()`. Known баг MAUI + WinUI.

**Решение:** плоский список + `BindableLayout` вместо `CollectionView.IsGrouped`.

### 3. `FeatureGate.IsPremium` не может быть `const`

Если `const bool IsPremium = false`, WinUI инлайнит значение при компиляции и крашится.

**Решение:** `public static bool IsPremium { get; } = false;`

### 4. Android сборка: XAGNM7009

`missing native code generation state for architecture 'Arm64'` — баг SDK при мультиархитектурной сборке.

**Решение:** `-p:RuntimeIdentifier=android-arm64` (одна архитектура для RuStore — 99%+ устройств arm64).

## Выводы

**AI реально ускоряет разработку.** Но не заменяет:
- Знание платформы (MAUI, Android, WinUI — у каждого свои готчи)
- Архитектурные решения
- Умение читать stack trace и искать решения

**Кросс-платформа на MAUI работает**, но требует обходных путей. Не все контролы работают одинаково на Android и Windows.

**6000 строк за 10 дней** — это примерно x3 по сравнению с ручной разработкой. И это с тестами и публикацией в магазин.
